* Corrections found that the manuscript still needs

These are errors in the current text, all verified against the project's own archived
outputs. None has been written into the manuscript yet.

1. *Fig 6 caption is backwards.* It says domains "become more numerous" as features are
   added. Read from the saved metadata of the run that produced Fig 6, domain count *falls*:
   33 at depth 10 down to a plateau near 19-20.
2. *The Results overstate full depth.* They say the full feature space "gave the greatest
   spatial complexity and coherence of the depths we swept". Depths 1250, 1350, 1400 and
   1450 all score better on the published run's own saved ELSA.
3. *Field count.* 1,449 numerically distinct interaction fields, not 1,477. Twenty groups of
   identical rows, 32 redundant: 4 are Dropbox conflicted copies, the other 28 are the
   common minimum collapsing mechanisms that share a globally limiting partner. Seven GDF9
   mechanisms are one field.
4. *Control B's clustering backend is undisclosed.* The paper's headline control ran on the
   RcppHNSW/igraph substitute, not Seurat, and the manuscript says nothing about it. Line
   365 says the refit fields went "through the identical convolution, clustering, and
   scoring pipeline", which a reader will take to mean identical to Fig 6's pipeline. It
   was identical between the observed and permuted arms, which is what makes the control
   valid, but not identical to the main pipeline. Needs one sentence. The null cannot be
   cheaply re-clustered: the permuted fields were never saved, so redoing it means about
   800 core-hours of model refits.
5. *Uncertainty is computed then discarded.* Already corrected in the text (commit
   5c9e810), listed here so it is not "re-fixed".

* New experimental results, all committed

** Control A v2: the pairing does not drive the domains

`code-spatial-smoothing/controls/sweep/RESULTS-controlA.md`. Both defects that caused the
original withdrawal are fixed: clustering is deterministic, and the scramble is
exclusion-aware with zero real pairs remaining in any null.

Clean null on spatial coherence in both implementations. Substitute: 99 scrambles, z =
-0.60, and 24 of 99 beat the true pairing. Seurat: 19 scrambles, z = +1.73, and 17 of 19
beat it. The sign differs, which is what noise around a null looks like.

Not null on redundancy: the true pairing yields 1,449 distinct fields against a null of
about 1,424, z = +4.30 and +3.91. Real pairings collapse less than random ones.

*The response letter already commits us to this test.* R2.8 says the pair-shuffle control
"could now be run to a conclusion... we have not done so". It has been run. Reporting it is
not optional. Whether and how to report it is the biggest open decision.

** Feature-depth sweep: the depth effect is real, the published curve's shape is not

`RESULTS.md` and `RESULTS-seurat.md`. Randomizing which features enter at each depth
deconfounds depth from feature identity. Coherence improves about 3.1x from ten fields to a
thousand in Seurat and 3.9x from ten to 350 in the substitute, steeply to a few hundred and
slowly after. That supports the paper's underlying claim in a form the published experiment
could not establish.

The hump in the published curve (worse from depth 10 to ~150 before recovering) replicates
in both implementations under variance ordering and is absent under random ordering, so it
is an artifact of admitting features in variance order.

*Three claims were withdrawn* after Seurat failed to replicate them: that variance ordering
is actively harmful, that the lowest-variance fields are most useful, and that ordering
accounts for most of the reported effect. Those held only in the substitute.

** A reproducibility result stronger than anything in the manuscript

An independently written Seurat script on klone reproduced the published full-depth values
at ELSA(d50) 0.1236 against 0.1237 and 19 domains against 20. And clustering is bit-identical
across machines and library versions with one thread and a fixed seed, verified ARI exactly
1.000000 including graph construction.

* The win-criteria thread: what it is and where it stopped

The authors want to run an experiment comparing representations (no combination, common
minimum, product, each on raw and rescaled inputs) to decide whether the combination step
adds anything. The hard part is not the experiment, it is defining what "wins" means.

Design history, all in `Submission_PLOSOne/submission-2/`:
- `win-criteria-proposal.org` is the live document, currently v3.
- `win-criteria-review-v2.md` and `win-criteria-review-v3.md` are two independent reviews.
  Both found structural flaws. Read them before touching the design.

*Decisions already made by AOZ:* use posterior draws as the perturbation; run the full
factorial (six arms, three representations x two input scales); test whether 999 spatial
shifts are computationally affordable before committing to them.

*Blocking checks already run and passed* (klone job 39422583): clustering is exactly
reproducible, and reusing the neighbor graph across resolutions gives 7.7x, so the budget
buys 20 replicates rather than 5.

*Where it stopped.* The v3 primary measure (count of domains supported by held-out gene
differential expression) was found to have an undefined bias direction: whether it rewards
or punishes fragmentation depends on an unspecified "sibling" definition. Rather than patch
it, the measure was replaced with *cross-validated predictive fit*: score a partition by how
well it predicts held-out gene expression in spatial blocks it was not fitted on. A spurious
split adds a parameter without improving out-of-sample prediction; a real split improves it.
That removes the sibling definition, the spatial null, the alpha, the multiplicity
correction and the minimum domain size all at once.

*That measure is being calibrated right now* by `code-spatial-smoothing/controls/sweep/cv-fit-measure.R`,
which runs label surgery on the published 20-domain partition: arbitrary splits of the
purest domains (score should not rise), splits of the least pure domains along the reference
annotation's own boundary (should rise), merges (should fall), boundary jitter (should
fall). *If it fails those, it must not go into v4.* Check `cv-fit-calibration.csv` and
`cv-fit.log` in that directory.

v4 has not been written. It should incorporate the v3 review's seven items plus whatever the
calibration shows.

* Practical notes for the next session

- *Seurat only.* Standing decision 2026-08-20. Do not use the RcppHNSW/igraph substitute for
  anything that will be reported; the two give non-comparable numbers. See the project
  memory note of the same name.
- *klone access.* Duo-only, so a bare `ssh` fails. But `~/.ssh/config` sets
  `ControlPersist 4h` on host `hyak`, so once AOZ runs `ssh hyak` the socket lets Claude
  rsync and submit for four hours. The socket expires silently; test with
  `ssh -o BatchMode=yes hyak echo ok` before assuming.
- *klone has no R module.* Use `module load apptainer/1.1.5` then
  `apptainer exec --env R_LIBS_USER=$HOME/Rlib-ctrlB $HOME/containers/geospatial.sif Rscript ...`,
  and prepend the user library inside the script or the image's ggplot2 3.5.1 shadows the
  4.0.3 Seurat needs.
- *Resource frugality is a hard requirement.* Measured baselines: Seurat clustering 3.8 GB
  and about 30 min at depth 350; the substitute 2.8-3.7 GB and 1-4 min. Size to measured
  MaxRSS x 2. An earlier over-request in this project reserved roughly 5 TB for a real need
  under 500 GB.
- *`Sup7 - Clustering vs Features.R` cannot run standalone.* It needs
  `options(future.globals.maxSize)` raised, which is set only in Sup5, so Sup7 works only if
  Sup5 was sourced first in the same session. Belongs in the R2.9 documentation; not yet
  added.
- *SLURM `--export` splits its value on commas*, so passing a comma-separated list as an
  environment variable silently truncates it. Use colons.
- *Figures are scripted now.* `compose-figs-3-4.R`, `compose-fig-5.py`,
  `compose-fig-5-transposed.py`, `graphical-abstract.R`, `regenerate-fig5.R`,
  `fig5-input-panels.R`, `fig5-summary-panels.R`, all in
  `Submission_PLOSOne/submission-2/figures-regenerated/`. The manuscript previously had to
  admit no layout script existed; that is no longer true and R2.9 could say so.
